# 视觉交互特效草案模板
将用户的初始 Prompt 扩写为面向用户确认的视觉创意草案。草案只呈现经过归纳的设计结论，说明用户最终会看到什么、如何互动以及不同动作产生什么画面变化。

草案不是完整 Brief，不展示内部分类、参考标签、实现参数、资产规划、制作流程或验收内容。

```markdown
- **动态标题**

  内容
```

## 组织原则
草案固定使用以下四个部分，每个部分只输出一个自然语言段落，不使用字段列表、编号步骤或多层子标题。

- **一句话概念**
用一段自然语言概括效果主题、核心体验和最终整体画面。只保留用户理解方案所必需的信息，不解释内部效果分类、参考依据或规划过程。

- **画面设计**
用一段自然语言综合描述主要对象、数量、位置、排列、遮挡、颜色、材质、轮廓、图案、光效和画面层级。相关内容必须合并表达，不拆成“主体与构图”“视觉风格”“画面层级”等多个字段。

- **互动流程**
用一段自然语言按照实际发生顺序串联初始状态、用户动作、即时反馈、状态切换、结果展示和重新开始。每个动作都要说明对应画面变化，但不得拆成逐条操作说明。

- **结果与补充**
用一段自然语言概括候选与结果数量、不同结果内容、最终文案、复位方式和必要的边界行为。只保留影响用户体验的结论，不输出检测参数、实现细节和验收要求。

## 层级与篇幅限制

- 草案正文只使用 `- **一句话概念**`、`- **画面设计**`、`- **互动流程**` 和 `- **结果与补充**` 四个一级项目。
- 每个标题后保留一个空行，正文使用两个空格缩进。
- 每个部分只能包含一个自然语言段落。
- 每个段落使用 2 至 4 句话，避免过长。
- 四个部分合计只保留方案摘要，不复述完整意图分析。
- 除四个一级项目外，不使用其它项目符号、编号步骤、表格或 Markdown 标题。
- 不得将每个动作、状态、参数或视觉属性分别展开。

## 扩写原则

1. **最终画面优先**：先明确用户真正想看到的视觉结果，再组织作用对象、输入映射和动态过程。明确的画面目标优先于模糊的技术称呼（如“粒子”“材质”“后处理”只是手段）。
2. **作用范围明确**：区分全屏、主体、局部语义区域、特定对象和周边空间。必须从描述中识别效果作用于何处，并说明哪些区域不受影响，确保语义区域隔离。
3. **输入映射闭合**：识别手势、表情、动作、触摸、录制或持续时间触发；明确输入如何映射到位置、范围、强度、颜色、形变、显隐等属性。离散动作需说明阶段变化，连续输入需明确跟随趋势和消失后的行为。
4. **视觉层次清晰**：区分核心效果、辅助反馈和环境氛围。主效果、辅助反馈应形成清晰层次，辅助元素不得遮蔽主体或破坏语义逻辑。
5. **动态过程完整**：草案必须形成“输入或触发 → 核心视觉变化 → 动态反馈 → 消散、恢复或稳定保持”的闭合链路，补全效果成立所需的最小生命周期。
6. **现实物理可信度**：扩写现实世界的动态现象时，主动写出决定该现象身份的状态演化、相互作用、耗散和边界反馈等适用行为；用户不需要提供物理或实现术语，这些固有行为不算额外创意。不得用只模仿单帧外形的动画替代必要的连续变化。草案只描述可见行为，具体模拟方法、状态资源和 Pass 结构留到 Brief 技术路线。
7. **最小合理补全**：仅补齐使视觉目标可理解、互动映射可执行和动态过程连续所必需的内容。可以确定影响视觉方案的对象数量和结果数量；平滑系数、检测阈值、稳定时间等实现参数不进入草案。
8. **参考内容内化**：提取参考图或视频中的构图、材质、色彩和运动特征，并直接写成最终画面描述。不得向用户输出参考类型标签、证据分类或“不继承哪些内容”等内部处理说明。
9. **歧义处理与能力边界**：忠实表达意图，不因能力暂缺就主动降级。通过上下文、因果关系和视觉语义排除非关键歧义；只有多个解释会导致不同的作用对象、输入源或核心互动关系时，才由 Planner 发起澄清。

## 用户可见表达边界

草案直接展示给用户，必须使用自然、直观的视觉设计语言。

### 摘要原则

Planner 可以在内部完整分析参考内容、视觉参数、交互状态、时序、资产数量和验收要求，但不得把完整分析直接展示给用户。

输出草案时必须进行归纳：

- 将多个构图参数总结为整体构图关系。
- 将颜色、材质、轮廓和光效总结为统一视觉风格。
- 将多个检测状态和时间参数总结为连续、稳定的交互体验。
- 将资产规划总结为用户能看到的对象与结果，不输出生产信息。
- 将验收条件转化为最终画面要求，不出现“验收”“必须通过”等措辞。
- 只有对象数量、结果数量、结果身份和关键交互顺序可以明确保留。

### 可以展示

- 效果名称和一句话概念。
- 最终画面中的对象、数量、位置、比例和遮挡关系。
- 用户动作与画面反馈。
- 用户能够直接感知的颜色、材质、轮廓、图案、光效和动画节奏。
- 候选数量、不同结果及重新开始方式。
- 用户明确要求显示的最终文案。

### 不得展示

- `screen_effect`、`asset_effect`、`hybrid_effect` 等内部效果类型枚举。
- `layout_reference`、`style_reference`、`asset_reference`、`motion_sequence` 等参考证据标签。
- “参考依据”“Brief 类型”“资产路由”“生成器”“对象合同”等内部规划术语。
- 平滑系数、检测阈值、稳定毫秒数、丢失容忍时间、索引计算等实现参数。
- 视觉资产 key、文件名、对象 ID、字段名或接口名称。
- “验收画面”“验收标准”“必须通过”“检查项”等交付审核措辞。
- “不继承人物身份”“参考图仅用于……”等内部证据处理说明。

### 转写规则

- `效果类型：hybrid_effect` 不输出；直接描述“保留实时相机画面，并叠加可交互的独立视觉对象”。
- `layout_reference + style_reference` 不输出；直接描述最终采用的构图、配色和材质。
- 检测稳定时间与平滑系数不输出；改写为“动作识别保持稳定，切换过程平滑，不因短暂丢失而闪烁”。
- “验收画面”不单独输出；将必要的最终观感合并进“画面表现”或“结果变化”。
- 参考图处理规则只供内部推理，不向用户解释证据分类。

## 意图还原细则

生成草稿前，必须从用户 Prompt 中识别并关联以下事实，确保逻辑一致：

- **语义还原**：不得因为多个视觉名词并列就拆成独立效果。每个元素的职责由它与作用对象、输入映射和最终画面的关系共同确定。
- **推断补全**：用户未完整说明链路时，补全使效果成立的最小结构，确保输入、作用范围和视觉响应一一对应。
- **数量拆分**：存在候选、结果或重复对象时，分别识别逻辑结果池数量、同时可见实例数量和可复用素材数量，不得将三者混为同一数量。
- **标准体系识别**：主题具有公认的完整内容体系时，优先识别其标准范围；画面一次能够显示多少对象，只决定可见实例数量，不决定完整结果池数量。
- **候选与结果识别**：存在抽取、选择、随机结果或逐项揭晓时，识别完整候选集合、结果数量和结果差异，不得把多个不同结果概括为一个通用结果。
- **子集限制**：只有用户明确要求精选、部分、简化版或指定数量时，才允许从标准内容体系中选取子集。
- **歧义过滤**：同一主题存在多个标准范围且会显著改变结果内容时，优先读取项目默认约定；没有默认约定时交给 Planner 澄清，不得根据画面容量自行选择。

## 意图理解正误对比示例（仅作为意图理解方向示例，禁止复制使用）

用户输入：张开手掌时，让身体周围出现蓝色能量场，手移动时带出光轨，握拳后能量聚拢并消失，人物本身不要变色。

### 错误示例

```markdown
  在画面上添加蓝色互动特效。张开手掌显示粒子，移动手掌产生光轨，握拳后显示结果。
```

错误原因：
- 没有说明效果具体作用范围。
- 没有描述能量场与光轨的视觉关系。
- 没有说明人物本身保持原样。
- 没有形成完整的初始、互动、结束和恢复流程。
- 所有内容堆在一个段落中，缺少结构。

### 正确示例

```markdown
# 蓝色能量场手势

- **一句话概念**

  用户张开手掌后，身体周围会浮现半透明蓝色能量场，移动手掌可以拉出连续光轨，握拳后能量向身体中心聚拢并消失；人物与真实背景始终保持原样。

- **画面设计**

  蓝色能量主要环绕身体轮廓和双手运动路径，具有明亮核心、透明外缘和沿轮廓流动的细密光纹；光轨位于能量场上方但不覆盖面部，使人物肤色、服装和背景保持清晰。

- **互动流程**

  初始状态只显示相机画面，张开手掌后能量场平滑出现，移动手掌时光轨连续跟随，握拳后所有能量向中心收拢并逐渐熄灭；短暂失去手部时画面保持连续，长时间没有输入后自然恢复初始状态。

- **结果与补充**

  快速抖动或不完整手势不会触发状态切换，所有视觉变化只发生在身体轮廓外侧和手部轨迹周围，不改变人物与背景本身。
```

## 输出格式示例

```markdown
# [效果名称]

- **一句话概念**

  使用一段自然语言概括效果主题、核心体验和整体画面。

- **画面设计**

  使用一段自然语言综合描述主体、数量、构图、位置、视觉风格、光效和层级关系。

- **互动流程**

  使用一段自然语言按照时间顺序串联初始状态、用户动作、画面反馈、结果展示和重新开始。

- **结果与补充**

  使用一段自然语言概括候选与结果、最终文案、复位方式和必要的边界表现。
```


## 输出规则

1. 草案固定输出“一句话概念、画面设计、互动流程、结果与补充”四个部分。
2. 四个部分必须使用 `- **标题**` 的 Markdown 列表格式，不使用 Markdown 标题。
3. 每个标题后保留一个空行，正文使用两个空格缩进。
4. 每个部分只能输出一个自然语言段落，每段控制在 2 至 4 句话。
5. 除四个标题前的项目符号外，正文不使用项目符号、编号步骤、字段标签或表格。
6. 草案只输出归纳后的设计结论，不复述完整意图分析。
7. 多候选或多结果效果必须保留候选数量、结果数量和不同结果身份，但应合并在“结果与补充”的自然段中。
8. 每个用户动作必须写明对应的画面反馈，但应合并在“互动流程”的自然段中。
9. 不输出效果名称标题、效果类型、参考依据、参考标签、实现参数、资产信息、代表画面或验收标准。
10. 不输出 `screen_effect`、`asset_effect`、`hybrid_effect`、视觉资产 key、对象 ID 或制作术语。
11. 只输出填写完成的 Markdown 草案，不输出模板说明、分析过程或额外解释。
